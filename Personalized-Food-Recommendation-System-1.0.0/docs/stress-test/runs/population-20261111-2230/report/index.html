我們怎麼測？

先新增 100 個測試帳號，每人放入 3 筆隨機飲食紀錄，讓測試時真的有資料可查。接著用程式同時操作多個不同帳號，實際向網站發送請求；不是只在紙上估算。

  1. 測「大家一起進來」：分批模擬 1、5、10、20、30、50、75、100 人，同時建立連線。每個人要完成查食物、查飲食與歷史紀錄、新增一筆、修改、確認內容及刪除；有一步失敗，就不算這個人整輪成功。
  2. 測「登入後一直用」：先讓這一批人連上，再重複上述讀寫操作，每輪結束休息 4–6 秒，模擬使用者閱讀或思考。每種人數先測 1 分鐘，通過的最高人數再測 3 分鐘。
  3. 看會不會斷線或弄錯資料：每 5 秒檢查網站是否回應，同時驗證新增、修改、刪除的內容。測完再逐帳號確認原本 3 筆紀錄仍正確，測試臨時紀錄已刪除。

本次以「大部分請求 2 秒內回應、錯誤比例低於 1%」作為品質參考。測試的是程式對網站的資料操作，沒有包含網頁畫面載入、照片辨識或 AI 功能。
