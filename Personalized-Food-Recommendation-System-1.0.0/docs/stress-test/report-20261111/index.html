大量使用者同時進來時，哪裡變慢？

每位使用者以新 Session 執行一次 /auth/user 與七項依序讀寫操作，最後多做一次刪除清理。首請求包含建立連線及伺服器處理的總耗時，尚無法分離 DNS、TCP、TLS、Funnel 或後端各自耗時。後續操作重用同一 Session，但沒有逐一驗證底層 socket 是否重用。

50 人首請求 P95 為 17.54 秒，單次最慢 22.48 秒；後續七項 API 合併 P95 為 0.426 秒。30 人重測的首請求 P95 為 8.95 秒。這是短時間流程結果，不能據此認定可長時間穩定供 50 人使用。先前「5 人是容量上限」的判讀已撤回：它只反映混合統計跨過了 2 秒參考線。

18 或 19 是 Tailscale 官方限制嗎？

查閱 Tailscale Funnel 官方限制文件（2026-11-11）：列出連接埠、TLS 與不可自行調整的頻寬限制，未列出 18／19 條同時連線的上限。文件沒有列出不代表無限容量。Funnel 提供公開存取，Serve 供 tailnet 內部存取；tailnet 成員／裝置配額不能直接當網站訪客上限。

這次唯讀探測由同一台電腦依序新建並保留 Session：前 19 次 HTTP 200，第 20 次在約 0.72 秒後 TLS EOF；關閉一個既有 Session、等待 2 秒後，新 Session 再次成功。這支持路徑中存在與佔用連線相關的現象，但未量測當時真正存活的 TCP socket 總數，亦未辨別單一 IP／全域／客戶端限制，不能稱為已證實的 Tailscale 上限。
