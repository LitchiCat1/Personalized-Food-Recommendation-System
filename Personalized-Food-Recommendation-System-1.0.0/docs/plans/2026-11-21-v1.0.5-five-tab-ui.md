# NutriLens v1.0.5 五頁 UI 優化企劃

2026-11-21 · 本機 `v1.0.5` · 基準提交 `731c357` · 首頁、趨勢與辨識已完成本機實作與 Web 驗收，整合驗收待完成。

## 1. 目的與範圍

讓使用者在手機上快速完成「記一餐、看攝取量、找下一餐」，同時讀得懂營養來源與健康提醒。以目前導覽的五個主頁為範圍。洞察屬於趨勢頁，今日餐點紀錄入口位於首頁。沿用 Expo 路由、共用元件與設計代幣，將營養、風險、資料來源、份量與個人設定視為既有行為合約。

## 2. 共用設計

- 首頁與辨識結果以餐盤掃描與營養摘要建立辨識度。店家、趨勢、我的優先讓使用者掃讀與操作，使用區段標題、留白、細分隔線整理資訊。
- 沿用 `frontend/constants/theme.ts`。淺色基底 `#F7FAF8`、內容底 `#FFFFFF`、正文 `#14201B`、動作綠 `#1F9D72`、資料藍 `#2F80ED`、提醒橘 `#F59E0B`。深色沿用對應代幣。風險保留狀態文字及圖示，驗收文字和互動狀態對比。
- 標題使用既有 h1/h2/h3，正文用系統字型，繁體中文與數字都要清楚。kcal、g、mg 等數字使用等寬數字字形並對齊單位。權限、同步與失敗提示靠近受影響的操作。
- 以 390 × 844 為手機基準，固定主要控制的點擊區至少 44 px 或相應裝置單位。保留手機底部導覽與桌面側欄，檢查相機模式、鍵盤與安全區。共用元件的變更以多頁確實共用的需求為限。

## 4. 實作順序與驗收

1. **建立基準並處理判讀錯誤。** 先用隔離測試資料重現五頁關鍵狀態，留存手機與桌面基準。從首頁熱量環和趨勢圖開始，使用同一組營養門檻核對數字與警示，再調整共用標題、數值與狀態元件。
2. **整理辨識到記錄流程。** 以同一組測試照片或固定回應驗證成功、待確認與失敗。對照送出前後食材名稱、來源、分量與營養合計，確認拍照、重試、若有候選則確認及加入紀錄各自可操作。
3. **整理店家與我的。** 驗證篩選、地圖與清單的選取同步，再驗證個人資料與安全條件儲存。依畫面必要性調整分組、間距、文字換行與操作優先序。
4. **整合驗收與結案。** 使用 375、390、430、768、1024、1440 px 檢查 Web，涵蓋觸控、Tab 焦點、文字放大與空白／載入／錯誤。Android 補驗相機、回到畫面的狀態、鍵盤及長按。使用隔離帳號或測試資料，執行 `npm run typecheck`、`npm run lint`、`npm run build:web` 與受影響的 `test:nutrition`、`test:scanner`、`test:records`、`test:trends`、`test:insights`、`test:safety`、`test:location`、`test:indexing`。依五頁表格逐項記錄結果與截圖。版面遮擋、資料誤讀和主流程回歸須在結案前修正，其餘後續構想另列。

## 6. 手機與桌面版型

以下為實作起點。區塊順序由上往下，桌面並排部分由左往右閱讀。手機沿用系統字型及既有導覽，高度由內容、鍵盤與安全區共同決定。

| 頁面 | 手機 | 桌面 |
| --- | --- | --- |
| 首頁 | 日期與同步狀態 → 熱量摘要與鈉上限 → 拍照辨識 → 其他營養素 → 今日餐點。需要注意的警示靠近對應數值或餐點。 | 上方摘要與拍照入口，下面並排營養進度與今日餐點。 |
| 辨識 | 模式列 → 當前輸入 → 結果摘要 → 待處理項 → 可記錄食材 → 加入今日紀錄。找到待處理項時，可從結果摘要直接到該區。 | 左欄為模式與當前輸入，右欄為結果、份量與提交。相機預覽沿用專注拍攝畫面。 |
| 店家 | 定位與篩選 → 搜尋 → 結果數與清單／地圖切換 → 店家與菜單入口。首次有結果時預設清單。 | 篩選橫列，下方地圖與清單並排。選取店家後在對應位置呈現同一筆摘要。 |
| 趨勢 | 日期區間與樣本摘要 → 熱量圖 → 鈉圖 → 洞察 → 其他營養平均。 | 區間摘要在上方，熱量與鈉圖在同一欄，上下相鄰。洞察與其他平均值放在旁欄。 |
| 我的 | 保留個人資料／安全條件／飲食目標三段切換。安全條件先列疾病，再列過敏原。上限編輯器放在對應疾病列下。 | 保留三區並排，欄寬不足時由既有斷點承接。各區的編輯、儲存、錯誤訊息都留在本區。 |

共用排版以現有代幣為起點。手機左右 16 px，區段間距 24 px，區段內間距 8–12 px。主標 26、區段標題 20、正文 15、輔助字 13，字級尊重裝置或瀏覽器設定。長名稱和狀態允許換行，加減和其他圖示按鈕保有 44 px 點擊範圍與可讀名稱。橫向寬度不足時先讓操作列換行，維持數值與單位可辨。鍵盤焦點依閱讀順序移動，選取與警告有文字或圖示輔助。對比以一般文字 4.5:1 為驗收起點，按鈕前景色依實際配色核對。

## 7. 各頁操作和邊界

### 7.1 首頁

- 熱量環集中呈現「已攝取／目標」，旁邊只補「剩餘」或「已超出」。鈉用「已攝取／每日上限」。每日與單餐提醒分別放在總覽與對應餐點，兩者依各自的判定資料。
- 初次載入以固定高度的預留版面和破折號表示。同步成功且當日沒有紀錄時顯示真實零值及拍照入口。有同帳號、同日期可用資料時顯示原數值及暫存提示。讀取失敗且沒有可用資料時，數值保持空值並提供重試。
- 驗收連續切換帳號、跨日、重試成功、儲存餐點後返回首頁、修改份量後重新整理。用全日鈉在上限內但其中一餐有單餐提醒的測試資料，核對兩種提示同時正確。

### 7.2 辨識

- 拍照主按鈕放在第一個互動區。相簿、營養標示、菜單與手動搜尋保留獨立入口。辨識中鎖住相同提交，結果摘要顯示「可記錄 X 項」「待確認 Y 項」，營養總計只採用符合現有記錄條件的項目。
- 食材列依序顯示品名、來源或待確認原因、重量控制、換算後的實際份量營養。每 100 g、每份與整包的基準各自明示，僅在既有資料提供時顯示。候選與廠商標示預覽須帶有預覽狀態，沿用現行的採用條件。
- 只有待確認項時，提供現有補資料方式。混合結果以明確提示標示哪些項目會加入今天。送出中、已寫入、待同步與寫入後刷新失敗各自顯示，重試沿用既有去重及同步流程。
- 驗收同一張餐盤有可記錄與待確認項、選擇整包後手動改為半包、重量手輸與增減、切換模式後舊回應抵達、重複點擊提交、拒絕相機後改走相簿。營養標示沿用既有每份重量及整包備援規則，另測包重與份數換算不一致，以及自動查詢營養期間的提交鎖。

### 7.3 店家

- 半徑與店家類型放在同一搜尋區。變更篩選後提示「套用篩選」，舊結果若仍可見須標出其對應條件。搜尋中停止重複提交。結果更新以店家 ID 協調標記及清單，原店家仍在結果中時保留選取，否則依現有預設選取規則處理。
- 店家列依序顯示店名、距離、營業狀態與菜單資料狀態，優先呈現「查看菜單」「導航」。AI 摘要、網站與建檔放在次要操作區，保留來源狀態。地圖不可用時顯示清單及外部導航。
- 採用備援搜尋中心時，地圖與清單標示「預設搜尋中心」，距離以該中心計算。保留上一批結果時，同步保留該批的搜尋中心與篩選條件。
- 驗收拒絕定位、篩選後零結果、切到地圖後仍選中原店、搜尋或建檔時的連續點擊，以及結果更新後原選取店家消失。手機補測地圖手勢與頁面捲動。

### 7.4 趨勢

- 顯示實際日期、有效紀錄天數、餐數與平均每日熱量。缺日以現行的連續區段規則切分，圖表日期統一為月／日，跨年由摘要顯示年份。
- 熱量與鈉圖的上限取圖表參考門檻和區間最大值中較大者，尺度最小值為 1。目標線與資料柱採同一比例，超標分類直接使用實際門檻。零上限時任何正攝取都須顯示超標。最新日靠日期或外框強調，超標仍以文字及風險樣式呈現。
- 趨勢的熱量達標區間沿用目標的 85% 到 115%，含兩端。目標線標為「目標」，超過 115% 的風險標為「偏高」。首頁的「已超出目標」則直接與當日目標比較。同樣是 2,000 kcal 的目標，2,100 kcal 在首頁顯示超出 100 kcal，在趨勢仍屬達標區間。鈉圖與洞察共用「攝取量大於每日上限」的判定。
- 比較使用既有資料精度，驗收時核對門檻附近的數字不會因畫面取整而看似與結果矛盾。參考線在零點時，預留標籤空間，仍可讀到「每日上限 0 mg」。
- 以鈉上限 2,000 mg、紀錄為 1,800／2,000／2,300／3,200 mg 驗收等於上限與超出上限，以及兩個超標柱可比較。另測零上限、最後一日熱量偏高、單日、七日、跨年及中間缺日。

### 7.5 我的

- 保留帳號、基本資料、身體與熱量摘要。姓名與 Email 可換行。個人資料尚未載入、尚未填寫以及儲存失敗分別使用對應狀態與操作。
- 疾病列顯示啟用狀態、以及「使用預設」「已自訂」或「已儲存自訂值，目前停用」等對應狀態。疾病啟用後在當列展開上限編輯。營養素名稱與單位、加減按鈕、輸入欄、恢復預設和儲存維持清楚的閱讀順序。
- 將「設定已儲存，但每日進度未刷新」視為獨立狀態，提供既有重新整理操作。驗收單擊 g／mg 步進、長按和放開、輸入小數、取消勾選再啟用、儲存失敗保留草稿、逐項恢復預設和首頁同步。

基準與改版各拍一張 390 px 及 1440 px 的代表狀態。其餘斷點記錄異常與修正後實測。用既有測試指令驗證受影響功能，介面行為由瀏覽器及 Android 補足。每批更新本企劃的進度、結果及尚待驗證項。功能驗收記錄以隔離資料建立，實際模型與地圖有代表案例需要複驗時另記測試環境與結果。

跨頁驗收用同一個測試帳號走完兩條流程。

1. 首頁點「拍照辨識」，選一組含可記錄及待確認食材的結果，調整份量並儲存。回首頁核對餐數只增加一筆、總量符合採用食材，再到趨勢核對同日資料。
2. 在「我的」修改鈉上限並儲存，核對首頁和趨勢顯示的上限。取消勾選疾病確認上限改用適用值，再勾選確認自訂值恢復。確認既有餐點仍顯示相同營養數值。

第一批交付以首頁、熱量環與趨勢圖為主。先用同一組固定回應重現首頁未就緒及鈉柱截頂，再做畫面調整。若需要共用元件調整，記錄受影響頁面並一併檢查。其餘頁面依第 4 節分批處理。

## 9. 首批實作紀錄

- 首頁合併熱量摘要，鈉攝取與每日上限並列。未載入或失敗且無今日資料時顯示空值，保留同帳號、來源和日期最後可用的結果，並提供重試。單餐警示獨立顯示，紀錄管理按鈕移入今日餐點區。
- 趨勢顯示實際日期區間、有效天數、餐數和平均每日熱量。熱量與鈉圖相鄰，柱高與參考線共用比例，最新一天與偏高或超標可同時判讀。極窄和放大字體下改以逐日文字呈現。
- 自動檢查已通過：型別、lint、Web 匯出；營養 153 項、紀錄 13 項、趨勢 6 項、洞察 13 項。新增三個圖表案例，涵蓋鈉柱比例、零上限和最新日風險。
